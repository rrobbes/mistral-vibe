🎣 Les Hooks de Mistral Vibe

Étendez, contrôlez et personnalisez votre agent IA à chaque étape de son exécution. La feature qui vous donne le pouvoir de reprogrammer le comportement de Mistral Vibe sans toucher à son code.

❓ Pourquoi les hooks ? 📚 Concept Fondamental 🎯 Cas concrets

📚 Le Concept Fondamental

🎣 Définition Simple et Précise

Un hook (ou "crochet" en français) est un point d'interception asynchrone dans le cycle de vie de Mistral Vibe. C'est un mécanisme qui permet :

  • D'intercepter des événements clés (avant/après l'exécution d'outils, après un tour d'agent)
  • D'exécuter votre propre code en réponse à ces événements
  • De modifier ou bloquer le flux d'exécution normal
  • Le tout via des processus externes qui communiquent par JSON via stdin/stdout

Analogie : Imaginez un hook comme un poste de contrôle sur une autoroute. Chaque fois qu'une voiture (une action de l'agent) passe, vous pouvez :

  • 🟢 La laisser passer (allow)
  • 🔴 La bloquer (deny) avec une raison
  • 🟡 La modifier (rewrite input, transform output)

🔄 Les 3 Types de Hooks et Leur Rôle

Mistral Vibe propose 3 points d'interception distincts, chacun avec une finalité précise :

⏳

PRE_TOOL

Quand : Avant qu'un outil ne soit exécuté

Pourquoi : Valider, modifier ou bloquer l'appel d'outil

Exemple : Bloquer les commandes bash dangereuses

✅

POST_TOOL

Quand : Après qu'un outil a été exécuté

Pourquoi : Transformer la sortie, journaliser, auditer

Exemple : Ajouter un timestamp à toutes les sorties

🔄

POST_AGENT

Quand : Après chaque tour de conversation complet

Pourquoi : Déclencher des actions post-réponse, injecter du contexte

Exemple : Notifier Slack qu'une tâche est terminée

✨ L'astuce : Sans hooks, Mistral Vibe exécute simplement : Requête → LLM → Outil → Réponse.
Avec hooks, vous pouvez intervenir à chaque étape pour :

  • Valider avant l'exécution (PRE_TOOL)
  • Transformer après l'exécution (POST_TOOL)
  • Réagir après un tour complet (POST_AGENT)

❓ Pourquoi les Hooks Existents-Ils ?

🎯 La Problématique Initiale

Mistral Vibe est un outil puissant, mais par défaut, il fonctionne comme une boîte noire :

1. Requête Utilisateur
"Ouvre le fichier X"
→
2. LLM Décide
"J'appelle read_file"
→
3. Outil Exécuté
read_file("X")
→
4. Réponse à l'Utilisateur
Contenu du fichier

Le problème : Vous n'avez aucun contrôle sur ce qui se passe entre la requête et la réponse.

Si vous voulez :

  • ❌ Bloquer certains outils pour des raisons de sécurité
  • ❌ Modifier les arguments d'un appel d'outil avant exécution
  • ❌ Valider les réponses avant qu'elles ne soient affichées
  • ❌ Journaliser toutes les actions pour l'audit
  • ❌ Intégrer Mistral Vibe avec vos systèmes internes

...vous êtes bloqué.

🚫

Sans Hooks : La Solution Impossible

Pour personnaliser le comportement, vous devriez :

  1. Forker le dépôt Mistral Vibe
  2. Modifier le code source de l'agent loop
  3. Gérer vos propres mises à jour
  4. Perder tous les bénéfices de la communauté

Résultat : ❌ Complexe, risqué, non maintenable

✅

Avec Hooks : La Solution Élégante

Les hooks vous permettent de :

  1. Définir des points d'interception dans un fichier TOML
  2. Écrire vos propres scripts (Python, Bash, Node.js...)
  3. Les exécuter automatiquement aux moments clés
  4. Modifier ou bloquer le flux si nécessaire

Résultat : ✅ Simple, flexible, maintenable

Philosophie : Mistral Vibe est conçu selon le principe Open/Closed : fermé pour la modification (vous ne touchez pas au code source), ouvert pour l'extension (vous ajoutez vos hooks).

🏗️ Les Piliers de la Conception

Les hooks de Mistral Vibe reposent sur 4 principes fondamentaux :

🎯

Principe 1 : Séparation des Préoccupations

Le code core reste propre et simple. Votre logique métier vit à l'extérieur dans vos hooks.

⚡

Principe 2 : Communication Standardisée

Tout passe par JSON sur stdin/stdout. N'importe quel langage peut implémenter un hook.

🔗

Principe 3 : Intégration Non-Intrusive

Les hooks sont optionnels. Sans configuration, Mistral Vibe fonctionne normalement.

🛡️

Principe 4 : Sécurité par défaut

Timeout, isolation des processus, validation des réponses. Les hooks ne peuvent pas casser l'agent.

✨ À Quoi Servent les Hooks ?

Les hooks vous permettent d'implémenter des stratégies transverses qui s'appliquent systématiquement à toutes vos interactions avec l'agent. Voici les 6 cas d'usage principaux :

🔒

1️⃣ Sécurité & Contrôle d'Accès

Problème : Empêcher l'exécution d'actions dangereuses ou non autorisées.

Solution : Hooks PRE_TOOL qui valident les appels avant exécution.

hook_pre_tool_security.py 
#!/usr/bin/env python3
import json
import sys

# Lire l'invocation depuis stdin
invocation = json.load(sys.stdin)

# Vérifier si c'est un outil bash
if invocation.get("tool_name") == "bash":
    command = invocation.get("tool_input", {}).get("command", "")
    
    # Bloquer les commandes dangereuses
    dangerous_commands = ["rm -rf", "chmod -R", ":(){ :|:& };:"]
    if any(dangerous in command for dangerous in dangerous_commands):
        print(json.dumps({
            "decision": "deny",
            "reason": f"Commande dangereuse détectée : {command[:50]}"
        }))
        sys.exit(0)

# Autoriser par défaut
print(json.dumps({"decision": "allow"}))
sys.exit(0)
🔄

2️⃣ Transformation des Données

Problème : Modifier systématiquement les entrées/sorties des outils.

Solution : Hooks PRE_TOOL pour modifier les inputs, POST_TOOL pour modifier les outputs.

hook_post_tool_timestamp.py 
#!/usr/bin/env python3
import json
import sys
from datetime import datetime

invocation = json.load(sys.stdin)

# Ajouter un timestamp à la sortie
output = invocation.get("tool_output_text", "")
timestamp = datetime.now().strftime("%Y-%m-%d %H:%M:%S")

# Modifier la sortie
print(json.dumps({
    "decision": "allow",
    "hook_specific_output": {
        "additional_context": f"\n---\n[Generé le {timestamp}]"
    }
}))
sys.exit(0)
📊

3️⃣ Audit & Journalisation

Problème : Garder une trace de toutes les actions pour le debugging ou la conformité.

Solution : Hooks POST_TOOL et POST_AGENT qui journalisent dans un fichier ou une base.

hook_post_agent_audit.py 
#!/usr/bin/env python3
import json
import sys
from pathlib import Path

invocation = json.load(sys.stdin)

# Journaliser dans un fichier
log_file = Path("~/vibe_audit.log")
log_entry = {
    "timestamp": invocation.get("timestamp"),
    "session_id": invocation.get("session_id"),
    "event": "agent_turn_completed"
}

log_file.write_text(json.dumps(log_entry) + "\n", append=True)

print(json.dumps({"decision": "allow"}))
sys.exit(0)
🔗

4️⃣ Intégration Externe

Problème : Connecter Mistral Vibe à vos outils ou APIs internes.

Solution : Hooks POST_AGENT qui déclenchent des actions externes.

hook_post_agent_slack.py 
#!/usr/bin/env python3
import json
import sys
import requests

invocation = json.load(sys.stdin)

# Notifier Slack
webhook_url = "https://hooks.slack.com/services/YOUR/WEBHOOK"
message = {
    "text": f"✅ Tâche terminée dans Mistral Vibe (Session: {invocation.get('session_id')})"
}

try:
    requests.post(webhook_url, json=message)
except:
    pass  # Ne pas bloquer l'agent si Slack est indisponible

print(json.dumps({"decision": "allow"}))
sys.exit(0)
🧠

5️⃣ Enrichissement du Contexte

Problème : Ajouter automatiquement des informations contextuelles (date, version, etc.).

Solution : Hooks POST_AGENT qui injectent du contexte.

hook_post_agent_context.py 
#!/usr/bin/env python3
import json
import sys
from datetime import datetime
import socket

invocation = json.load(sys.stdin)

# Ajouter du contexte système
context = f"""
Contexte système :
- Date: {datetime.now().strftime('%Y-%m-%d %H:%M:%S')}
- Machine: {socket.gethostname()}
- Utilisateur: {invocation.get('session_id', 'unknown')}
"""

print(json.dumps({
    "decision": "allow",
    "system_message": context
}))
sys.exit(0)
✅

6️⃣ Validation & Qualité

Problème : S'assurer que les actions respectent vos règles métier.

Solution : Hooks PRE_TOOL qui valident les paramètres avant exécution.

hook_pre_tool_validation.py 
#!/usr/bin/env python3
import json
import sys
import re

invocation = json.load(sys.stdin)

# Vérifier que les fichiers se terminent par un saut de ligne
if invocation.get("tool_name") == "write_file":
    content = invocation.get("tool_input", {}).get("content", "")
    if not content.endswith("\n"):
        print(json.dumps({
            "decision": "deny",
            "reason": "Le contenu du fichier doit se terminer par un saut de ligne"
        }))
        sys.exit(0)

print(json.dumps({"decision": "allow"}))
sys.exit(0)

🔍 Comparaison avec d'autres Approches

⚖️ Hooks vs Modification du Code Source

Critère Modification du Code Hooks
Maintenabilité ❌ Difficile (code mélangé) ✅ Facile (séparation claire)
Portabilité ❌ Spécifique à une version ✅ Portable entre projets
Mises à jour ❌ Conflits possibles ✅ Indépendant du code core
Isolation ❌ Risque d'effets de bord ✅ Processus séparés
Collaboration ❌ Requiert PR sur le repo ✅ Chacun gère ses hooks

⚠️ Attention : Modifier le code source de Mistral Vibe pour ajouter vos fonctionnalités revient à "forker" le projet. Vous perdrez le bénéfice des mises à jour et devrez maintenir votre propre version.

⚖️ Hooks vs Plugins

Critère Plugins Hooks
Complexité ❌ API complexe à apprendre ✅ Simple : JSON stdin/stdout
Flexibilité ❌ Limité aux points d'extension prévus ✅ Peut tout faire (accès complet aux données)
Langage ❌ Souvent limité à un langage ✅ N'importe quel langage
Intégration ❌ Requiert une API spécifique ✅ Standard : processus + JSON
Sécurité ⚠️ Variable selon l'API ✅ Isolation par processus + timeouts

ℹ️ Inspiration : Les hooks de Mistral Vibe sont inspirés des Git Hooks et des Webhooks : un mécanisme simple mais puissant basé sur des événements et des appels de processus externes.

🎯 Cas d'Usage Concrets

Voici des scénarios réels où les hooks apportent une valeur ajoutée immense :

🏢 Entreprise - Sécurité Renforcée

🔒 Protection contre les commandes dangereuses

Contexte : Votre entreprise utilise Mistral Vibe en production avec accès à des outils système.

Problème : Vous voulez éviter que les utilisateurs (ou l'IA) n'exécutent des commandes dangereuses comme rm -rf / ou cat /etc/shadow.

Solution : Un hook PRE_TOOL qui vérifie toutes les commandes bash avant exécution et bloque celles qui sont sur une liste noire.

✅ Résultat : Votre environnement est protégé. Toutes les commandes dangereuses sont bloquées avant exécution, avec un message clair expliquant pourquoi.

📜 Juridique - Conformité RGPD

📜 Audit et conformité

Contexte : Vous travaillez dans un secteur réglementé (santé, finance, etc.) et devez respecter le RGPD ou d'autres réglementations.

Problème : Vous devez consigner toutes les interactions avec l'IA, y compris les appels d'outils, les réponses générées, et les décisions prises.

Solution : Un hook POST_AGENT qui journalise toutes les conversations dans un système centralisé avec horodatage, session ID, et métadonnées complètes.

✅ Résultat : Vous avez un audit complet de toutes les interactions, prêt pour les vérifications de conformité. Vous pouvez prouver que l'IA n'a pas eu accès à des données sensibles.

🚀 DevOps - Automatisation CI/CD

🤖 Intégration CI/CD

Contexte : Votre équipe utilise Mistral Vibe pour générer du code ou de la documentation.

Problème : Vous voulez que chaque génération de code déclenche automatiquement des tests ou des déploiements.

Solution : Un hook POST_TOOL qui déclenche votre pipeline CI/CD après que Mistral Vibe ait généré du code via write_file.

✅ Résultat : Votre workflow DevOps est entièrement automatisé : code généré → tests → déploiement. Plus besoin d'intervention manuelle.

📁 Multi-Projets - Configuration Spécifique

📁 Règles par projet

Contexte : Vous travaillez sur plusieurs projets avec des règles différentes. Certains projets autorisent l'accès à des outils sensibles, d'autres non.

Problème : Vous avez besoin de règles de sécurité et de comportement différentes pour chaque projet.

Solution : Des fichiers de configuration TOML différents par projet qui définissent quels hooks s'appliquent. Les hooks peuvent lire le contexte du projet actuel.

✅ Résultat : Chaque projet a ses propres règles de sécurité et de comportement, sans conflit. Le passage d'un projet à l'autre est transparent.

💡 Productivité - Enrichissement Intelligent

💡 Contexte automatique

Contexte : Vous utilisez Mistral Vibe quotidiennement pour diverses tâches.

Problème : Vous devez souvent répéter des informations contextuelles (date, heure, version du projet, etc.) ou l'IA pose des questions répétitives.

Solution : Un hook POST_AGENT qui injecte automatiquement ces informations dans le contexte de la conversation, et un hook PRE_TOOL qui valide que toutes les informations nécessaires sont présentes.

✅ Résultat : L'IA connaît toujours le contexte de votre environnement, ce qui améliore la pertinence des réponses et réduit la friction.

👥 Pour Qui sont Faits les Hooks ?

Les hooks ne sont pas réservés aux experts. Ils s'adressent à tous ceux qui veulent reprendre le contrôle sur leur expérience avec Mistral Vibe.

👨‍💻

Développeurs

Pour vous si :

  • Vous voulez intégrer Mistral Vibe dans vos workflows existants
  • Vous devez ajouter des fonctionnalités spécifiques à votre domaine
  • Vous voulez automatiser des tâches avec l'IA
  • Vous avez besoin de valider ou transformer les données

Niveau requis : Intermédiaire (comprendre JSON et les processus)
Temps estimé : 1-2 heures pour les premiers hooks

👩‍🚀

Ops / DevOps

Pour vous si :

  • Vous devez sécuriser l'accès à l'IA dans votre organisation
  • Vous voulez auditer toutes les actions pour la conformité
  • Vous devez intégrer Mistral Vibe dans votre pipeline CI/CD
  • Vous voulez limiter les risques liés à l'utilisation de l'IA

Niveau requis : Avancé (scripting, sécurité, réseaux)
Temps estimé : 1 journée pour une configuration complète

👨‍💼

Responsables Sécurité

Pour vous si :

  • Vous devez vous conformer à des réglementations strictes
  • Vous voulez limiter les risques liés à l'utilisation de l'IA
  • Vous devez auditer les actions de l'IA
  • Vous voulez appliquer des politiques de sécurité uniformes

Niveau requis : Débutant (configuration TOML simple)
Temps estimé : 30 minutes pour configurer des règles basiques

👩‍🏫

Chefs de Projet / Managers

Pour vous si :

  • Vous voulez standardiser les workflows de votre équipe
  • Vous devez assurer la cohérence entre différents projets
  • Vous voulez ajouter du contexte projet automatique
  • Vous voulez limiter l'accès à certains outils

Niveau requis : Débutant (configuration simple)
Temps estimé : 1 heure pour configurer des hooks par projet

🧠

Utilisateurs Avancés

Pour vous si :

  • Vous voulez personnaliser votre expérience
  • Vous avez des besoins spécifiques non couverts par défaut
