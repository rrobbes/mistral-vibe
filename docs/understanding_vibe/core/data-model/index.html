§1

Vue d'ensemble

types.py ne s'exécute pas : c'est le vocabulaire commun du moteur. Backends, boucle d'agent, outils, sessions et App Server échangent les mêmes objets, définis ici.

Survolez ou cliquez une flèche, un composant ou le socle types.py. Faites défiler le schéma horizontalement.

Schéma conceptuel : il montre les données échangées, pas chaque appel réel. En gris : modèles publics de l'App Server, qui ne viennent pas de types.py.

Deux moteurs d'agent

Depuis cette version, le moteur par défaut est le Unified Harness, un runtime externe avec ses propres types : il n'utilise de types.py que SessionMetadata et ScheduledLoop. Le schéma montre le moteur Python (vibe --legacy-harness), celui qui utilise tout le modèle de données. Détails dans le rapport.

Cliquez une famille pour voir où ses types circulent.

        Ce que je n'affirme pas

        Singleton, Factory (GoF) : absents de types.py. AgentStats.create_fresh() est une méthode de fabrique statique, un idiome, pas le patron Factory. Adapter : présent, mais dans les backends LLM qui traduisent chaque API en LLMChunk, pas dans types.py (voir le travail sur core/backend).

        §6

        Conclusion

        1. Le Data Model fournit un vocabulaire commun au moteur. 48 classes, importées par 84 fichiers du moteur.
        2. Des modèles structurés et validés permettent aux composants de communiquer. Messages, fragments additionnables, événements typés.
        3. Cette organisation sépare le cœur de l'agent des interfaces et des fournisseurs. Aucune interface n'importe types.py ; chaque backend produit des LLMChunk.

        Et après ? Les types de ce fichier relient plusieurs sujets du projet :

        Backends LLMproduisent les LLMChunk Agent Loop (PR #24)émet les événements, possède la MessageList PermissionsApprovalRequestEvent, approval_source OutilsToolCall, ToolResultEvent SessionsSessionMetadata, transcription Configurationinstantané dans SessionMetadata.config Unified Harnessle moteur par défaut, avec ses propres types : sujet encore à documenter
