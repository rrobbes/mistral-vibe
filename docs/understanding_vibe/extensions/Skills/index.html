What Are Skills

Skills are Markdown files with YAML frontmatter that teach Vibe how to better assist you with specific tasks or workflows. Think of them as "plugins" or "extensions" for Vibe's brain.

Each Skill contains custom instructions that load automatically when relevant or can be invoked manually. They bridge the gap between Vibe's general AI capabilities and your specific needs.

Core Characteristics

  • ✓ Metadata: Name, description, configuration in YAML frontmatter
  • ✓ Instructions: Custom guidance for the AI in Markdown
  • ✓ Scope: Global (all projects) or Project-specific
  • ✓ Access Control: User-invocable or model-only
  • ✓ Shareable: Across projects, teams, and via the registry

Use Cases

Skills can be created for virtually any specialized task:

  • ✓ Code review checklists and security audits
  • ✓ Git workflow automation and commit standards
  • ✓ Framework-specific expertise (Django, React, Python, etc.)
  • ✓ Documentation writing guidelines and best practices
  • ✓ Project-specific conventions, styles, and workflows

name: code-review
description: Load when reviewing pull requests

user-invocable: true
---

# Code Review Guidelines

## Security
- Check for SQL injection
- Verify no hardcoded secrets

## Quality
- All tests must pass
- Code coverage checked
- Type hints present

Integration with Plugins, Subagents & Hooks

In the Mistral Vibe codebase, Skills don't work in isolation. They are part of a larger extension ecosystem that includes Plugins, Subagents, and Hooks, each serving distinct but complementary purposes.

How They Work Together

These extension mechanisms can be combined for powerful workflows:

  • ✓ Skills + Plugins: A Skill provides instructions for using a Plugin's custom tools. For example, a data-analysis Skill teaches Vibe how to use a pandas tool from a Data Science Plugin.
  • ✓ Skills + Subagents: A Skill provides the instructions that a Subagent should follow. When spawning a Subagent for code review, you might load a code-review Skill to guide its analysis.
  • ✓ Skills + Hooks: Hooks can automatically load relevant Skills based on file changes or project context. For example, a Hook might detect you're working in a Django project and auto-load the django-expert Skill.
  • ✓ All Together: A Plugin adds new tools, a Skill provides instructions for using them, a Hook auto-loads the Skill when relevant, and a Subagent uses both to perform complex tasks autonomously.
ℹ

Extension Hierarchy: Plugins > Skills > Hooks > Subagents. Plugins provide the foundation, Skills add knowledge, Hooks add automation, and Subagents add autonomy.

Extension Ecosystem Flow
🛠 Plugins (Capabilities)  →  📚 Skills (Instructions)  →  ✅ Hooks (Automation)  →  👥 Subagents (Autonomy)

Skill Discovery Flow

SkillManager discovers Skills from multiple sources in a specific order. First match wins.

Discovery Order

vibe/core/skills/manager.py
def _discover_skills(self, config: VibeConfig) -> dict[str, SkillInfo]:
    skills: dict[str, SkillInfo] = {}
    
    # 1. Load built-in skills first (reserved names)
    for builtin in self._load_builtin_skills():
        skills[builtin.name] = builtin
    
    # 2. Scan config skill_paths
    for path in config.skill_paths:
        if path.exists():
            skills.update(self._discover_skills_in_dir(path, SkillScope.GLOBAL))
    
    # 3. Scan project skills directories
    for path in self._harness_files.project_skills_dirs:
        skills.update(self._discover_skills_in_dir(path, SkillScope.PROJECT))
    
    # 4. Scan user skills directories
    for path in self._harness_files.user_skills_dirs:
        skills.update(self._discover_skills_in_dir(path, SkillScope.GLOBAL))
    
    # 5. Load registry skills (if enabled)
    if config.experimental_enable_registry_skills:
        skills.update(self._discover_registry_skills())
    
    return skills
vibe/core/skills/manager.py
def _discover_skills_in_dir(self, base: Path, scope: SkillScope) -> dict[str, SkillInfo]:
    """Walk directory and find all SKILL.md files"""
    skills = {}
    
    for skill_dir in base.iterdir():
        if not skill_dir.is_dir():
            continue
        
        skill_file = skill_dir / "SKILL.md"
        if not skill_file.is_file():
            continue
        
        # Parse and validate the skill
        skill_info = self._try_load_skill(
            skill_file, 
            source=SkillSource.LOCAL, 
            scope=scope
        )
        
        if skill_info:
            skills[skill_info.name] = skill_info
    
    return skills
ℹ

First Match Wins: If the same Skill name appears in multiple sources, the first one discovered (based on the order above) is used. Built-in Skills always win since they're loaded first.

Skill Invocation

Manual Invocation

When a user types /skill-name in the chat, the agent loop parses and processes it:

vibe/core/skills/manager.py
def parse_skill_command(self, text_prompt: str) -> ParsedSkillCommand | None:
    """Parse /skill-name commands from user input"""
    stripped = text_prompt.strip()
    
    # Must start with /
    if not stripped.startswith("/"):
        return None
    
    # Extract skill name and optional extra instructions
    parts = stripped[1:].split(None, 1)
    skill_name = parts[0].lower()
    extra_instructions = parts[1] if len(parts) > 1 else None
    
    # Lookup skill
    skill_info = self.get_skill(skill_name)
    if skill_info is None or not skill_info.user_invocable:
        return None
    
    # Return parsed command
    return ParsedSkillCommand(
        name=skill_name,
        content=skill_info.prompt,
        extra_instructions=extra_instructions
    )
Usage in Agent Loop
# In vibe/core/agent/loop.py

def _handle_user_message(self, message: str):
    # Check for skill command
    parsed = self._skill_manager.parse_skill_command(message)
    if parsed:
        # Add skill to context
        self._context.add_skill(parsed.name, parsed.content)
        
        # Include extra instructions if any
        if parsed.extra_instructions:
            self._context.add_user_message(parsed.extra_instructions)
        
        return
    
    # Normal processing...
    self._context.add_user_message(message)

Automatic AI Invocation

When the AI determines a Skill is relevant, it's automatically added to the context:

vibe/core/agent/loop.py
# Before model inference
def _prepare_context(self, user_message: str) -> str:
    context = self._build_base_context()
    
    # Check for model-invocable skills
    for skill in self._skill_manager.available_skills.values():
        if skill.model_invocable:
            # Model decides if Skill is relevant based on description
            if self._model_should_invoke(user_message, skill):
                context += f"\n\n--- Skill: {skill.name} ---\n"
                context += skill.prompt
    
    return context
Relevance Check
def _model_should_invoke(self, message: str, skill: SkillInfo) -> bool:
    """Check if skill description matches user message"""
    # Simple implementation: check if description keywords appear in message
    description_keywords = skill.description.lower().split()
    message_lower = message.lower()
    
    # More sophisticated: use embedding similarity or LLM judgment
    return any(keyword in message_lower for keyword in description_keywords)

Registry Integration

Vibe can fetch Skills from a central registry, so you don't have to create everything from scratch.

How the Registry Works

The registry is a central catalog of Skills published by Mistral AI and the community. Think of it like a package repository (similar to npm, pip, or apt).

Browsing Available Skills

You can discover Skills published to the registry and add them to your local setup. Each Skill in the registry has:

  • ✓ A unique identifier (like mistralai/code-review-pro)
  • ✓ Multiple versions
  • ✓ A description explaining its purpose
  • ✓ The complete Skill content (instructions, configuration, etc.)

Adding Skills from the Registry

When you want to use a Skill from the registry, you pin it to your skills.toml file. This tells Vibe: "I want to use this specific Skill". Vibe then downloads and caches it locally.

~/.vibe/skills.toml
[[skills]]
name = "code-review"
skill_id = "mistralai/code-review-pro"
version = "latest"
description = "Professional code review assistant"

[[skills]]
name = "django-expert"  
skill_id = "mistralai/django-guide"
version = 2
description = "Django framework specialist"
ℹ

Global vs Project Skills: You can pin Skills globally (in ~/.vibe/skills.toml - available everywhere) or per-project (in .vibe/skills.toml - only in this project). Project pins override global ones with the same name.

What Happens When You Update?

When Vibe starts or when you run a sync command, it checks your pinned Skills:

  1. Read your manifest - Checks what Skills you've pinned
  2. Check local cache - Sees if you already have the requested version
  3. Download if missing - Fetches any Skills not in your cache
  4. Validate and store - Saves Skills safely with atomic writes (preventing corruption)
  5. Make them available - Skills are now ready to use just like local ones

"""Unit tests for Skill Pydantic models"""
import pytest
from pydantic import ValidationError
from vibe.core.skills.models import SkillMetadata, SkillScope, SkillSource


class TestSkillMetadata:
    def test_valid_skill_metadata(self):
        """Test creation of valid skill metadata"""
        metadata = SkillMetadata(
            name="my-skill",
            description="A test skill"
        )
        assert metadata.name == "my-skill"
        assert metadata.description == "A test skill"
        assert metadata.user_invocable is True

    def test_invalid_name_too_long(self):
        """Test that names longer than 64 chars are rejected"""
        with pytest.raises(ValidationError) as exc_info:
            SkillMetadata(
                name="a" * 65,  # 65 chars - too long
                description="Test"
            )
        assert "max_length" in str(exc_info.value)

    def test_invalid_name_pattern(self):
        """Test that names with invalid chars are rejected"""
        with pytest.raises(ValidationError) as exc_info:
            SkillMetadata(
                name="My-Skill",  # Uppercase - invalid
                description="Test"
            )
        assert "pattern" in str(exc_info.value)

    def test_valid_name_with_hyphens(self):
        """Test that names with hyphens are valid"""
        metadata = SkillMetadata(
            name="my-test-skill",
            description="Test"
        )
        assert metadata.name == "my-test-skill"

tests/core/skills/test_manager.py
"""Integration tests for SkillManager"""
import pytest
from pathlib import Path
from vibe.core.skills.manager import SkillManager
from vibe.core.skills.models import SkillSource, SkillScope


class TestSkillDiscovery:
    def test_discovery_order_builtin_wins(self, skill_manager, tmp_path):
        """Test that built-in skills take precedence over local ones"""
        # Create a local skill with same name as built-in
        skill_dir = tmp_path / "skills" / "vibe"
        skill_dir.mkdir(parents=True)
        (skill_dir / "SKILL.md").write_text("""
---
name: vibe
description: Local vibe skill
user-invocable: true
---
# Local Vibe Skill
""")
        
        # Add to skill paths
        skill_manager._config.skill_paths = [tmp_path / "skills"]
        
        skills = skill_manager._discover_skills()
        
        # Built-in should win, not the local one
        assert "vibe" in skills
        assert skills["vibe"].source == SkillSource.BUILTIN

    def test_discovery_multiple_sources(self, skill_manager, tmp_path):
        """Test discovery from multiple sources"""
        # Create project and user skills
        project_dir = tmp_path / "project" / ".vibe" / "skills"
        user_dir = tmp_path / "user" / ".vibe" / "skills"
        
        project_dir.mkdir(parents=True)
        user_dir.mkdir(parents=True)
        
        # Create a skill in both locations
        (project_dir / "test-skill" / "SKILL.md").write_text("""
---
name: test-skill
description: Project skill
---
""")
        (user_dir / "test-skill" / "SKILL.md").write_text("""
---
name: test-skill
description: User skill
---
""")
        
        # Project should take precedence over user
        skills = skill_manager._discover_skills()
        assert "test-skill" in skills
        assert skills["test-skill"].scope == SkillScope.PROJECT

    def test_discovery_with_filters(self, skill_manager, tmp_path):
        """Test that disabled skills are filtered out"""
        # Create a skill
        skill_dir = tmp_path / "skills" / "disabled-skill"
        skill_dir.mkdir(parents=True)
        (skill_dir / "SKILL.md").write_text("""
---
name: disabled-skill
description: Should be filtered
---
""")
        
        # Configure to disable this skill
        skill_manager._config.disabled_skills = ["disabled-skill"]
        
        skills = skill_manager._discover_skills()
        
        # Should not appear in available skills
        assert "disabled-skill" not in skill_manager.available_skills


class TestSkillLoading:
    def test_load_from_cache(self, skill_manager, tmp_path):
        """Test that skills are cached after first load"""
        # Create a skill
        skill_dir = tmp_path / "skills" / "cached-skill"
        skill_dir.mkdir(parents=True)
        skill_file = skill_dir / "SKILL.md"
        skill_file.write_text("""
---
name: cached-skill
description: Test caching
---
# Content
""")
        
        # First load
        skill_manager._config.skill_paths = [tmp_path / "skills"]
        skill_manager._load_skills()
        
        # Modify the file
        skill_file.write_text("""
---
name: cached-skill
description: Modified
---
# Modified Content
""")
        
        # Should still return cached version
        skills = skill_manager._discover_skills()
        assert "cached-skill" in skills
        assert "Test caching" in skills["cached-skill"].description

class TestMultipleSkills:
    def test_multiple_skills_in_context(self, skill_manager, tmp_path):
        """Test that multiple relevant skills are added to context"""
        # Create multiple skills
        skills_data = [
            ("python-expert", "Load when working with Python", True, False),
            ("testing-expert", "Load when working with tests", True, False),
        ]
        
        for name, desc, user_inv, model_inv in skills_data:
            skill_dir = tmp_path / "skills" / name
            skill_dir.mkdir(parents=True)
            (skill_dir / "SKILL.md").write_text(f"""
---
name: {name}
description: {desc}
model-invocable: {str(model_inv).lower()}
---
# {name.title()} Skill
""")
        
        skill_manager._config.skill_paths = [tmp_path / "skills"]
        skill_manager._load_skills()
        
        # Check all skills are available
        assert skill_manager.get_skill("python-expert") is not None
        assert skill_manager.get_skill("testing-expert") is not None
        
        # Check both are model-invocable
        model_skills = [
            s for s in skill_manager.available_skills.values()
            if s.model_invocable
        ]
        assert len(model_skills) >= 2
