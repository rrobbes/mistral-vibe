⚙️ Configuration des Hooks

Apprenez à configurer vos hooks avec des fichiers TOML. Découvrez où placer vos fichiers, comment les structurer, et quelles options sont disponibles.

📝 Introduction à la Configuration

🎯 Pourquoi TOML ?

Mistral Vibe utilise le format TOML (Tom's Obvious Minimal Language) pour la configuration des hooks. Ce choix offre plusieurs avantages :

✅

Simple et Lisible

TOML est conçu pour être facile à lire et à écrire pour les humains.

📊

Structuré

Permet une hiérarchie claire avec des sections et des tableaux.

⚡

Sûr

TOML est déterministe et évite les pièges des autres formats.

📦

Standard

Format largement utilisé (Cargo, Hugo, Python config, etc.).

📁 Où Placer les Fichiers de Configuration ?

Mistral Vibe cherche les fichiers de hooks dans plusieurs endroits, selon le Harness Files Manager.

Ordre de priorité (du plus spécifique au plus général) :

  1. Projet (Project)
    .vibe/hooks.toml
    Spécifique à un projet, ne s'applique qu'à ce projet
  2. Plugin Projet (Project Plugin)
    .vibe/plugins/*/hooks.toml
    Hooks fournis par des plugins de projet
  3. Global (Global)
    ~/.vibe/hooks.toml
    S'applique à tous les projets pour l'utilisateur
  4. Plugin Global (Global Plugin)
    ~/.vibe/plugins/*/hooks.toml
    Hooks fournis par des plugins globaux
  5. Harness
    harness/runtimes/*/hooks.toml
    Hooks fournis par le harness (rarement utilisé)

ℹ️ Bon à savoir : Les hooks sont cumulatifs. Mistral Vibe charge tous les fichiers trouvés et les combine dans l'ordre de priorité. Si un hook a le même nom dans plusieurs fichiers, seul le premier est chargé.

📋 Structure de Base d'un Fichier TOML

🎨 Format Minimal

Un fichier de hooks TOML est un tableau de tables [[hooks]] :

.vibe/hooks.toml 
[[hooks]]
name = "mon-premier-hook"
type = "pre_tool"
command = "python3 /path/to/mon_hook.py"

[[hooks]]
name = "mon-deuxieme-hook"
type = "post_agent"
command = "bash /path/to/autre_hook.sh"

Champs obligatoires :

  • name - Nom unique du hook (string non vide)
  • type - Type du hook : "pre_tool", "post_tool", ou "post_agent"
  • command - Commande à exécuter (string non vide)

⚙️ Tous les Champs Disponibles

Champ Type Requis Valeur par défaut Description
name string ✅ Oui - Nom unique du hook. Doit être différent pour chaque hook.
type string ✅ Oui - Type de hook : "pre_tool", "post_tool", ou "post_agent"
command string ✅ Oui - Commande à exécuter. Peut être n'importe quelle commande shell valide.
match string | null ❌ Non null Filtre les outils. Seulement pour pre_tool et post_tool. Utilise la syntaxe de matching glob.
timeout float | null ❌ Non 60.0 Timeout en secondes. Si le hook prend plus de temps, il est tué.
strict boolean ❌ Non false Si true, une erreur dans le hook bloque l'exécution. Si false, l'erreur est ignorée (avec warning).
description string | null ❌ Non null Description du hook pour la documentation et le debugging.

📚 Exemples Complets de Configuration

🏠 Fichier TOML pour un Projet

Exemple d'un fichier .vibe/hooks.toml avec plusieurs hooks de types différents :

.vibe/hooks.toml 
# ============================================
# Hooks pour mon projet
# ============================================

# --- Sécurité : Bloquer les commandes bash dangereuses ---
[[hooks]]
name = "security-block-dangerous-bash"
type = "pre_tool"
command = "python3 ~/.vibe/hooks/security/block_dangerous_bash.py"
match = "bash"
timeout = 30
strict = true
description = "Bloque les commandes bash dangereuses comme rm -rf"

# --- Audit : Journaliser tous les appels d'outils ---
[[hooks]]
name = "audit-log-all-tools"
type = "post_tool"
command = "python3 ~/.vibe/hooks/audit/log_tool_call.py"
match = "*"
timeout = 10
strict = false
description = "Journalise tous les appels d'outils dans un fichier"

# --- Transformation : Ajouter timestamp aux sorties read_file ---
[[hooks]]
name = "transform-add-timestamp"
type = "post_tool"
command = "python3 ~/.vibe/hooks/transform/add_timestamp.py"
match = "read_file"
timeout = 5
strict = false
description = "Ajoute un timestamp aux sorties de read_file"

# --- Intégration : Notifier Slack après chaque tour ---
[[hooks]]
name = "integration-slack-notify"
type = "post_agent"
command = "node ~/.vibe/hooks/integration/slack_notify.js"
timeout = 15
strict = false
description = "Envoie une notification à Slack après chaque tour"

# --- Validation : Vérifier les écritures de fichiers ---
[[hooks]]
name = "validation-file-write"
type = "pre_tool"
command = "python3 ~/.vibe/hooks/validation/validate_file_write.py"
match = "write_file"
timeout = 10
strict = true
description = "Vérifie que les fichiers se terminent par un saut de ligne"

🌍 Fichier TOML Global

Exemple d'un fichier ~/.vibe/hooks.toml avec des hooks qui s'appliquent à tous les projets :

~/.vibe/hooks.toml 
# ============================================
# Hooks globaux pour tous mes projets
# ============================================

# --- Sécurité par défaut : Désactiver les outils sensibles ---
[[hooks]]
name = "global-security-disable-sensitive-tools"
type = "pre_tool"
command = "python3 /opt/vibe-hooks/security/disable_sensitive.py"
match = "*"
timeout = 20
strict = true
description = "Désactive les outils marqués comme sensibles dans ma config"

# --- Audit global : Journaliser dans un fichier central ---
[[hooks]]
name = "global-audit-central-log"
type = "post_agent"
command = "python3 /opt/vibe-hooks/audit/central_log.py"
timeout = 10
strict = false
description = "Journalise toutes les actions dans /var/log/vibe-audit.log"

# --- Contexte : Ajouter des informations utilisateur ---
[[hooks]]
name = "global-context-user-info"
type = "post_agent"
command = "python3 /opt/vibe-hooks/context/add_user_info.py"
timeout = 5
strict = false
description = "Ajoute automatiquement le nom d'utilisateur et la date"

🎯 Comprendre le Champ 'match'

❓ À quoi sert le champ 'match' ?

Le champ match permet de filtrer les appels d'outils pour lesquels un hook doit être exécuté. Il n'est disponible que pour les hooks de type pre_tool et post_tool.

⚠️ Important : Si vous essayez d'utiliser match avec un hook post_agent, vous obtiendrez une erreur de validation :
match is only valid for tool hooks (pre_tool / post_tool)

🔹 Match Exact

Le hook ne s'exécute que pour l'outil spécifié :

Match un outil spécifique 
[[hooks]]
name = "block-bash"
type = "pre_tool"
command = "python3 hooks/block_bash.py"
match = "bash"  # Ne s'applique qu'à l'outil 'bash'

S'applique à : Seulement bash
Non appliqué à : read_file, write_file, etc.

🌐 Match Wildcard (*)

Le hook s'exécute pour tous les outils :

Match tous les outils 
[[hooks]]
name = "log-all"
type = "post_tool"
command = "python3 hooks/log_all.py"
match = "*"  # S'applique à TOUS les outils

S'applique à : bash, read_file, write_file, etc.

🎭 Match avec Patterns

Utilisation de patterns glob pour matcher plusieurs outils :

Match avec patterns 
[[hooks]]
name = "log-file-operations"
type = "post_tool"
command = "python3 hooks/log_files.py"
match = "file_*"  # S'applique à file_read, file_write, etc.

[[hooks]]
name = "validate-read-operations"
type = "pre_tool"
command = "python3 hooks/validate_read.py"
match = "*read*"  # S'applique à read_file, read_dir, etc.

S'applique à : Tous les outils dont le nom correspond au pattern

📝 Match Multiple

Vous pouvez aussi utiliser une liste (mais attention, ce n'est pas supporté nativement) :

⚠️ Limitation : Actuellement, match n'accepte qu'une seule string. Pour matcher plusieurs outils, vous devez créer plusieurs hooks.

Solution : Plusieurs hooks 
# ❌ Ne fonctionne PAS :
# match = ["bash", "sh"]

# ✅ Solution : Deux hooks séparés
[[hooks]]
name = "block-bash"
type = "pre_tool"
command = "python3 hooks/block_shell.py"
match = "bash"

[[hooks]]
name = "block-sh"
type = "pre_tool"
command = "python3 hooks/block_shell.py"
match = "sh"

🔒 Le Mode Strict

❓ Que fait le mode strict ?

Le champ strict (booléen) contrôle le comportement du hook en cas d'erreur :

✅

strict = false (par défaut)

Si le hook échoue (erreur, timeout, sortie non-valide) :

  • ✅ L'erreur est ignorée
  • ✅ Un warning est affiché
  • ✅ L'exécution continue normalement
  • ✅ Le hook est considéré comme ayant retourné "allow"

Utilisation : Pour des hooks non-critiques (audit, logging, etc.)

❌

strict = true

Si le hook échoue (erreur, timeout, sortie non-valide) :

  • ❌ L'erreur bloque l'exécution
  • ❌ Une erreur est affichée
  • ❌ Selon le type de hook :
    • PRE_TOOL : L'outil est bloqué (deny)
    • POST_TOOL : La sortie est effacée
    • POST_AGENT : Aucun retry n'est injecté

Utilisation : Pour des hooks critiques (sécurité, validation, etc.)

⚠️ Attention avec strict=true :

  • Un bug dans votre hook peut casser votre workflow
  • Un timeout trop court peut aussi bloquer l'exécution
  • Testez toujours vos hooks en mode strict=false avant de les activer

🎯 Quand utiliser strict=true ?

Voici des scénarios où strict=true est recommandé :

🔒 Sécurité

Bloquer des actions dangereuses :

  • Commandes bash dangereuses
  • Accès à des fichiers sensibles
  • Appels d'outils non autorisés

Si le hook échoue, mieux vaut bloquer par défaut !

✅ Validation

Valider des contraintes métier :

  • Format des fichiers
  • Noms de variables
  • Structure des données

Si la validation échoue, l'action doit être bloquée.

🔄 Transformation Critique

Transformations essentielles :

  • Nettoyage de données sensibles
  • Chiffrement de données
  • Ajout de contexte obligatoire

Si la transformation échoue, il vaut mieux ne pas continuer.

✅ Bonnes pratiques :

  • Commencez toujours avec strict=false pendant le développement
  • Passez en strict=true une fois que le hook est stable et testé
  • Ajoutez des tests unitaires à vos hooks pour éviter les erreurs
  • Utilisez des timeouts raisonnables (timeout=30 par défaut)

🔍 Validation et Debugging

✅ Validation Automatique

Mistral Vibe valide automatiquement vos fichiers TOML lors du chargement. Voici les erreurs courantes et leurs solutions :

Erreur Cause Solution
command must not be empty Le champ command est vide ou manquant Ajoutez un champ command valide
hooks[0]: type - input should be 'pre_tool', 'post_tool', or 'post_agent' Le champ type a une valeur invalide Utilisez "pre_tool", "post_tool", ou "post_agent"
match is only valid for tool hooks Utilisation de match avec un hook post_agent Retirez le champ match ou changez le type de hook
Duplicate hook name: 'mon-hook' Deux hooks ont le même nom Changez le nom d'un des hooks
Failed to parse: ... Erreur de syntaxe TOML Corrigez la syntaxe de votre fichier

🐛 Debugging des Hooks

Si votre hook ne fonctionne pas comme prévu, voici comment le debugger :

1️⃣ Vérifier le chargement

Problème : Mon hook ne semble pas être exécuté.

Solution : Vérifiez que le fichier est chargé :

  • Le fichier existe-t-il au bon endroit ?
  • Le nom du hook est-il unique ?
  • Y a-t-il des erreurs de syntaxe TOML ?

Astuce : Lancez Mistral Vibe avec --log-level debug pour voir les logs de chargement.

2️⃣ Vérifier l'exécution

Problème : Mon hook est chargé mais ne fait rien.

Solution : Testez votre hook manuellement :

  • Exécutez la commande directement dans un terminal
  • Passez-lui un JSON valide sur stdin
  • Vérifiez qu'il retourne un JSON valide sur stdout
Test manuel 
# Tester un hook manuellement
echo '{"tool_name": "bash", "tool_call_id": "test", "session_id": "test", "transcript_path": "", "cwd": "/tmp", "tool_input": {"command": "ls"}}' | python3 my_hook.py

3️⃣ Vérifier les permissions

Problème : Mon hook plante avec une erreur de permission.

Solution : Vérifiez que :

  • Le fichier du hook est exécutable (chmod +x)
  • Le chemin est correct (absolu ou relatif)
  • L'interpréteur (python3, bash, etc.) est disponible
  • Le hook a les permissions nécessaires pour faire ce qu'il doit faire
Rendre un script exécutable 
chmod +x /path/to/my_hook.py

4️⃣ Vérifier les logs

Problème : Je ne comprends pas pourquoi mon hook ne fonctionne pas.

Solution : Activez les logs et vérifiez :

  • Les logs de Mistral Vibe (--log-level debug)
  • La sortie stderr de votre hook
  • Le code de retour de votre hook

Astuce : Ajoutez des logs dans votre hook :

Python avec logging 
import sys
import logging

logging.basicConfig(level=logging.DEBUG)

invocation = json.load(sys.stdin)
logging.debug(f"Received: {invocation}")

# ... votre logique ...

logging.debug(f"Returning: {response}")
print(json.dumps(response))

🌟 Bonnes Pratiques de Configuration

✅

Nommez vos hooks clairement

Utilisez des noms descriptifs :

  • security-block-dangerous-bash ✅
  • audit-log-all-tools ✅
  • hook1 ❌
  • test ❌
📝

Ajoutez des descriptions

Le champ description est optionnel mais très utile :

  • Pour vous souvenir du but du hook
  • Pour les autres développeurs
  • Pour le debugging
⚡

Choisissez des timeouts adaptés

  • Hooks simples (validation) : timeout = 5
  • Hooks moyens (transformation) : timeout = 15
  • Hooks complexes (appels API) : timeout = 30
  • Par défaut : timeout = 60

📁

Organisez vos fichiers

Structure recommandée : 

.vibe/
├── hooks.toml
└── hooks/
    ├── security/
    │   └── block_dangerous_bash.py
    ├── audit/
    │   └── log_tool_call.py
    ├── transform/
    │   └── add_timestamp.py
    └── integration/
        └── slack_notify.js
🔄

Versionnez vos hooks

  • Stockez vos hooks dans un dépôt Git
  • Versionnez les fichiers TOML
  • Documenter les changements

🧪

Testez vos hooks

  • Testez en mode strict=false
  • Vérifiez les entrées/sorties
  • Testez les cas d'erreur
