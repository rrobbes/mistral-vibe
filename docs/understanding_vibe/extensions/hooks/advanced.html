⚖️ Comparaison avec Autres Approches

🎯 Pourquoi Choisir les Hooks ?

Comparons les hooks avec d'autres mécanismes d'extension pour comprendre leurs forces et leurs limites.

⚖️ Hooks vs Modification du Code Source

Critère Modification du Code Hooks
Maintenabilité ❌ Difficile (code mélangé) ✅ Facile (séparation claire)
Portabilité ❌ Spécifique à une version ✅ Portable entre projets
Mises à jour ❌ Conflits possibles ✅ Indépendant du code core
Isolation ❌ Risque d'effets de bord ✅ Processus séparés
Collaboration ❌ Requiert PR sur le repo ✅ Chacun gère ses hooks
Complexité ⚠️ Nécessite de comprendre tout le codebase ✅ API simple et documentée

⚠️ Attention : Modifier le code source de Mistral Vibe pour ajouter vos fonctionnalités revient à "forker" le projet. Vous perdrez le bénéfice des mises à jour et devrez maintenir votre propre version.

⚖️ Hooks vs Plugins

Critère Plugins Hooks
Complexité ❌ API complexe à apprendre ✅ Simple : JSON stdin/stdout
Flexibilité ❌ Limité aux points d'extension prévus ✅ Peut tout faire (accès complet aux données)
Langage ❌ Souvent limité à un langage ✅ N'importe quel langage
Intégration ❌ Requiert une API spécifique ✅ Standard : processus + JSON
Sécurité ⚠️ Variable selon l'API ✅ Isolation par processus + timeouts
Performance ✅ Souvent optimisé ✅ Processus séparés, pas de surcharge

ℹ️ Inspiration : Les hooks de Mistral Vibe sont inspirés des Git Hooks et des Webhooks : un mécanisme simple mais puissant basé sur des événements et des appels de processus externes.

⚖️ Hooks vs Middleware

Dans certains frameworks, le middleware permet d'intercepter les requêtes. Comparons :

Critère Middleware Hooks
Couplage ⚠️ Couplé au framework ✅ Complètement découplé
Exécution ✅ Dans le même processus ✅ Processus séparé (plus sûr)
Points d'interception ✅ Définis par le framework ✅ Définis par l'utilisateur
Erreurs ❌ Peut crasher l'application ✅ Isolé, ne crash pas l'agent

🎨 Patterns Avancés

🔄 Pattern : Chaînage de Hooks

Combinez plusieurs hooks pour créer des workflows complexes.

Exemple : Validation → Transformation → Audit

Configuration 
[[hooks]]
name = "validate-input"
type = "pre_tool"
command = "python3 hooks/validate.py"
match = "*"
timeout = 5

[[hooks]]
name = "transform-input"
type = "pre_tool"
command = "python3 hooks/transform.py"
match = "*"
timeout = 5

[[hooks]]
name = "audit-action"
type = "post_tool"
command = "python3 hooks/audit.py"
match = "*"
timeout = 5

Flux : validate-input → transform-input → outil → audit-action

⚠️ Attention : Dans une chaîne de PRE_TOOL hooks, si un hook retourne "deny", les hooks suivants ne sont pas exécutés.

🎯 Pattern : Hooks Conditionnels

Activez ou désactivez des hooks en fonction du contexte.

hook_conditional.py 
#!/usr/bin/env python3
import json
import sys
import os

invocation = json.load(sys.stdin)

# Vérifier si on est en environnement de production
if os.getenv("ENV") == "production":
    # Appliquer des règles strictes
    if invocation.get("tool_name") == "bash":
        print(json.dumps({
            "decision": "deny",
            "reason": "Bash désactivé en production"
        }))
        sys.exit(0)
else:
    # Mode développement, tout est autorisé
    print(json.dumps({"decision": "allow"}))
    sys.exit(0)

📊 Pattern : Agrégation de Données

Collectez et agrégez des données à travers plusieurs appels d'outils.

hook_aggregate.py 
#!/usr/bin/env python3
import json
import sys
from collections import defaultdict

# Stockage en mémoire (ou utiliser Redis pour du persistent)
stats = defaultdict(lambda: {"count": 0, "total_duration": 0})

def main():
    global stats
    try:
        invocation = json.load(sys.stdin)
        
        tool_name = invocation.get("tool_name")
        duration = invocation.get("duration_ms", 0)
        
        # Mettre à jour les statistiques
        stats[tool_name]["count"] += 1
        stats[tool_name]["total_duration"] += duration
        
        # Loguer les stats périodiquement
        if stats[tool_name]["count"] % 10 == 0:
            avg_duration = stats[tool_name]["total_duration"] / stats[tool_name]["count"]
            print(f"Stats: {tool_name} - Count: {stats[tool_name]['count']}, Avg: {avg_duration:.2f}ms", file=sys.stderr)
        
        print(json.dumps({"decision": "allow"}))
        sys.exit(0)
    except Exception as e:
        print(json.dumps({"decision": "allow"}))
        sys.exit(1)

if __name__ == "__main__":
    main()

ℹ️ Note : Pour une agrégation persistante, utilisez une base de données ou Redis.

🐛 Debugging Avancé

🔍 Outils de Debugging

Voici les outils et techniques pour debugger vos hooks efficacement :

1. Logs Mistral Vibe

Commande : vibe --log-level debug

Ce que vous voyez :

  • Chargement des hooks
  • Exécution des hooks
  • Erreurs et warnings
  • Données d'invocation

2. Test Manuel

Tester un hook directement : 

echo '{"tool_name": "bash", "tool_call_id": "test", "session_id": "test", "transcript_path": "", "cwd": "/tmp", "hook_event_name": "pre_tool", "tool_input": {"command": "ls"}}' | python3 my_hook.py

Vérifiez :

  • Le hook retourne du JSON valide
  • Le code de sortie est 0
  • La réponse a la structure attendue

3. Logging dans le Hook

Exemple avec logging : 

import logging

logging.basicConfig(
    level=logging.DEBUG,
    format='%(asctime)s - %(levelname)s - %(message)s'
)

invocation = json.load(sys.stdin)
logging.debug(f"Input: {invocation}")

# ... traitement ...

logging.debug(f"Output: {response}")
print(json.dumps(response))

Redirigez stderr : 

python3 my_hook.py 2> hook_errors.log

4. Hook de Debug

Créez un hook qui loggue tout : 

#!/usr/bin/env python3
import json
import sys

invocation = json.load(sys.stdin)

with open("/tmp/hook_debug.log", "a") as f:
    f.write(json.dumps({
        "timestamp": "...",
        "hook": "debug",
        "input": invocation
    }) + "\n")

print(json.dumps({"decision": "allow"}))
sys.exit(0)

📊 Debugging des Performances

Identifiez les goulots d'étranglement dans vos hooks :

hook_with_profiling.py 
#!/usr/bin/env python3
import json
import sys
import time

start_time = time.time()

def main():
    invocation = json.load(sys.stdin)
    
    # Point 1
    t1 = time.time()
    
    # Traitement...
    
    # Point 2
    t2 = time.time()
    print(f"Phase 1: {t2-t1:.3f}s", file=sys.stderr)
    
    # Plus de traitement...
    
    # Point 3
    t3 = time.time()
    print(f"Phase 2: {t3-t2:.3f}s", file=sys.stderr)
    
    print(json.dumps({"decision": "allow"}))
    
    total = time.time() - start_time
    print(f"Total: {total:.3f}s", file=sys.stderr)

if __name__ == "__main__":
    main()

ℹ️ Astuce : Si un hook prend plus de 100ms, envisagez de l'optimiser ou de réduire son champ d'application avec match.
