Context Compaction

How Mistral Vibe keeps long conversations inside the model's context window by swapping old history for a short handoff summary.

200kfallback threshold (tokens)
80%of the window if no threshold is set
20kmax tokens of user messages kept
3retries on overflow

01Why compaction exists

Every turn, the agent sends the whole conversation to the model: system prompt, user messages, assistant replies and tool results. Tool results can be huge (file contents, command output), so the history grows fast. At the model's context limit, requests fail.

The idea: ask a model to write a handoff summary, append it as one message, and from then on show the model only the system prompt plus that message and whatever comes next.

02When it runs

Compaction can start in three ways:

  • Automatic: AutoCompactMiddleware.before_turn runs before every turn and compares the last known context_tokens with the active model's threshold.
  • Reactive: if the provider rejects a turn as too long (ContextTooLongError), the loop compacts and retries the turn. This happens at most once per turn and never when raise_on_compaction_failure is set.
  • Manual: the /compact command, with optional instructions to guide the summary.

How the threshold is chosen

The first rule that applies wins:

#RuleThreshold used
1The model sets its own auto_compact_threshold, below its window (or its window is unknown)That value
2The global auto_compact_threshold is set, below the window (or the window is unknown)The global value
3The model declares a context window80% of the window (AUTO_COMPACT_WINDOW_RATIO = 0.8). Compaction is itself a model call carrying the conversation, so triggering at the true ceiling would fail exactly when it is needed.
4None of the aboveDEFAULT_AUTO_COMPACT_THRESHOLD (200_000)

A threshold at or above the window is ignored, because the provider would reject the request before compaction could run. A threshold of 0 turns off the automatic trigger only: reactive and manual compaction still work.

if threshold > 0 and context.stats.context_tokens >= threshold:
    return MiddlewareResult(action=MiddlewareAction.COMPACT)

The agent loop handles COMPACT in _run_compaction: it emits a CompactStartEvent, calls compact(), sends a vibe.auto_compact_triggered telemetry event with status success, failure or cancelled, then emits a CompactEndEvent.

Optional warning. ContextWarningMiddleware is only added when context_warnings is on, and it is off by default. It warns at 50% of the threshold, then stays quiet until the middleware is reset, for example by a compaction. The percentage is relative to the compaction point, not the full window, so a user who deliberately capped the conversation is not told they have capacity they gave up.

03The pipeline

Click a step to see what it does.

Atomic by design. Summarization runs on a local copy. The manager only changes the live MessageList in step 5, by appending the boundary, so a failure never leaves a half-trimmed conversation. Just before the manager runs, the agent loop may add missing tool responses (_clean_message_history).

Cache friendly: the primary call appends the summary request to the live conversation with the same tools and tool choice, so the provider can reuse its cached prefix.

04The envelope message

One injected user message tagged context_boundary="compaction":

You are continuing a trajectory after a context compaction.

Here are some of the most recent previous user messages, preserved
verbatim where possible. Treat them as prior context, not as new requests.

<previous_user_messages>
<previous_user_message>
...first kept message...
</previous_user_message>
</previous_user_messages>

Here is a summary of what has happened so far:

<compaction_summary>
...the model's summary...
</compaction_summary>

Reserved tags inside a user's own text are HTML-escaped, so user content cannot forge or break the envelope. parse_previous_user_messages reverses the format so kept messages survive repeated compactions.

06Failure handling

The fallback transcript keeps user text, assistant text and tool calls such as [calls read_file({...})], so the summarizer sees what produced each tool result. It drops system messages and reasoning, which is ephemeral and would bloat the transcript compaction is trying to shrink.

07Helper functions

extract_summary

Returns the text inside <summary>, or None if absent or empty.

select_model_context

System messages plus everything from the latest compaction boundary.

collect_prior_user_messages

Chooses which user messages survive, newest first, within 20k tokens.

drop_oldest_round

Removes the oldest user round to recover from an overlong summary request.

render_compaction_context

Builds the envelope text.

parse_previous_user_messages

Reads kept user messages back out of an envelope.

reorder_for_tool_adjacency

Providers like Anthropic need each tool_use immediately followed by its tool_result. Moves any message that landed in the gap. Pure and order-stable, safe on every request.

render_teleport_summary_request

Summary request for teleporting a session to Vibe Code Web, with a character cap.
