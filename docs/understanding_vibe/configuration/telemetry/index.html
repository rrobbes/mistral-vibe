La télémétrie

Comment Vibe décrit certains événements de fonctionnement, construit leurs données et tente de les transmettre — sans interrompre le travail de l’agent.

01 · L’idée en une minute

Un événement décrit ce qui s’est passé

La télémétrie produit des événements applicatifs pour observer l’usage et le fonctionnement de Vibe : démarrage d’une session, requête au modèle, résultat d’un outil ou compaction.

ÉVÉNEMENT

vibe.request_sent

Une requête vers le modèle va être lancée. Cela ne dit pas si elle réussira.

PROPRIÉTÉS

Des mesures et catégories

Modèle, nombre de messages, longueur du contexte, type d’appel.

UTILITÉ

Observer

Relier ces faits à une session et repérer les usages, sans piloter l’agent.

Appel au LLMVibe transmet le contexte au modèle pour obtenir une réponse.
→
Événement de télémétrieVibe décrit cet appel avec des compteurs. C’est un envoi distinct, facultatif et asynchrone.
Exemple : « 5 messages de contexte, 1 234 caractères, modèle codestral ». Le texte du prompt n’est pas inclus dans le payload vibe.request_sent.
02 · Quatre pièces

Une chaîne courte, deux chemins d’entrée

Sélectionnez un fichier pour voir sa responsabilité. Les liens ouvrent le code local lorsque ce site est consulté dans le dépôt.

Legacy · Agent Loop

_loop.py calcule les compteurs et appelle directement send_request_sent().

Unified · App server

Le runtime tamponne les données de requête ; l’adaptateur les transmet via SessionTelemetry. Les deux chemins rejoignent TelemetryClient.

La déduplication de session.py concerne certains effets terminés, notamment les outils ; le parcours request_sent vide un tampon, sans déduplication générale des requêtes.

    04 · Pourquoi ce fonctionnement ?
    Rapide pour l’agent, prudent dans les conclusions
    Asynchrone
    asyncio.create_task() programme la tentative HTTP ; l’appelant n’attend pas sa réponse. Le client garde les tâches en attente et aclose() les attend à la fermeture normale.
    « Best-effort »
    Les exceptions du POST sont ignorées. Il n’y a ni file persistante ni nouvelle tentative dans ce module : la réception n’est pas garantie.
    Effets dédupliqués
    En unified, un même effet terminal peut apparaître dans plusieurs instantanés. claim(effect_id) évite de réémettre certains événements d’outil ou de compaction.
    Données envoyées
    request_sent contient des compteurs, le modèle et des métadonnées de session, pas le texte du prompt. Cela n’est pas une garantie générale d’anonymat pour tous les événements.
    L’option enable_telemetry et la présence d’une clé Mistral déterminent si l’événement est programmé. Une réponse HTTP sans exception, même en erreur, n’est pas traitée ici comme une preuve de réception.
    
    
    05 · À retenir
    Trois idées pour la suite
    Observer
    La télémétrie décrit certains événements de fonctionnement de Vibe.
    Centraliser
    Le module construit les événements, les enrichit et prépare leur transmission.
    Tenter
    L’envoi est asynchrone et tolérant aux erreurs ; leur réception n’est pas garantie.
    Dans notre groupe
    La configuration détermine notamment si la télémétrie est activée. Les permissions contrôlent l’autorisation de certaines actions des outils. La télémétrie observe certains événements ; elle n’applique pas les permissions.
