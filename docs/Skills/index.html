What is a Skill?

A Skill is a set of custom instructions that you can add to Mistral Vibe to teach it how to better assist you with specific tasks or workflows.

Think of Skills as "plugins" or "extensions" for Vibe's brain. Each Skill contains:

  • ✓ Metadata - Name, description, and configuration
  • ✓ Instructions - The actual guidance for the AI
  • ✓ Scope - Global (all projects) or Project-specific
  • ✓ Access Control - Who can invoke it (you or the AI)
my-skill/SKILL.md
---
name: code-review
description: Load when reviewing pull requests
user-invocable: true
---

# Code Review Guidelines
1. Check for security vulnerabilities
2. Verify all tests pass
3. Ensure code follows PEP 8
ℹ

Skills are Markdown files with YAML frontmatter. The YAML defines the metadata, and the Markdown body contains the instructions.

class SkillScope(str, Enum):

class SkillMetadata(BaseModel):

    name: str = Field(..., min_length=1, max_length=64,

    allowed_tools: list[str] = Field(default_factory=list)

    compatibility: Optional[str] = None

Skill Discovery Flow

SkillManager discovers Skills from multiple sources in a specific order. First match wins.

Discovery Order

vibe/core/skills/manager.py
def _discover_skills(self, config: VibeConfig) -> dict[str, SkillInfo]:
    skills: dict[str, SkillInfo] = {}
    
    # 1. Load built-in skills first (reserved names)
    for builtin in self._load_builtin_skills():
        skills[builtin.name] = builtin
    
    # 2. Scan config skill_paths
    for path in config.skill_paths:
        if path.exists():
            skills.update(self._discover_skills_in_dir(path, SkillScope.GLOBAL))
    
    # 3. Scan project skills directories
    for path in self._harness_files.project_skills_dirs:
        skills.update(self._discover_skills_in_dir(path, SkillScope.PROJECT))
    
    # 4. Scan user skills directories
    for path in self._harness_files.user_skills_dirs:
        skills.update(self._discover_skills_in_dir(path, SkillScope.GLOBAL))
    
    # 5. Load registry skills (if enabled)
    if config.experimental_enable_registry_skills:
        skills.update(self._discover_registry_skills())
    
    return skills
vibe/core/skills/manager.py
def _discover_skills_in_dir(self, base: Path, scope: SkillScope) -> dict[str, SkillInfo]:
    """Walk directory and find all SKILL.md files"""
    skills = {}
    
    for skill_dir in base.iterdir():
        if not skill_dir.is_dir():
            continue
        
        skill_file = skill_dir / "SKILL.md"
        if not skill_file.is_file():
            continue
        
        # Parse and validate the skill
        skill_info = self._try_load_skill(
            skill_file, 
            source=SkillSource.LOCAL, 
            scope=scope
        )
        
        if skill_info:
            skills[skill_info.name] = skill_info
    
    return skills
ℹ

First Match Wins: If the same Skill name appears in multiple sources, the first one discovered (based on the order above) is used. Built-in Skills always win since they're loaded first.

Skill Invocation

Skills can be invoked manually by users or automatically by the AI model.

Manual Invocation

When a user types /skill-name in the chat, the agent loop parses and processes it:

vibe/core/skills/manager.py
def parse_skill_command(self, text_prompt: str) -> ParsedSkillCommand | None:
    """Parse /skill-name commands from user input"""
    stripped = text_prompt.strip()
    
    # Must start with /
    if not stripped.startswith("/"):
        return None
    
    # Extract skill name and optional extra instructions
    parts = stripped[1:].split(None, 1)
    skill_name = parts[0].lower()
    extra_instructions = parts[1] if len(parts) > 1 else None
    
    # Lookup skill
    skill_info = self.get_skill(skill_name)
    if skill_info is None or not skill_info.user_invocable:
        return None
    
    # Return parsed command
    return ParsedSkillCommand(
        name=skill_name,
        content=skill_info.prompt,
        extra_instructions=extra_instructions
    )
Usage in Agent Loop
# In vibe/core/agent/loop.py

def _handle_user_message(self, message: str):
    # Check for skill command
    parsed = self._skill_manager.parse_skill_command(message)
    if parsed:
        # Add skill to context
        self._context.add_skill(parsed.name, parsed.content)
        
        # Include extra instructions if any
        if parsed.extra_instructions:
            self._context.add_user_message(parsed.extra_instructions)
        
        return
    
    # Normal processing...
    self._context.add_user_message(message)

Key Points:

  • ✓ Commands must start with /
  • ✓ Skill name is case-insensitive
  • ✓ user_invocable must be True
  • ✓ Extra text after command is preserved

Automatic AI Invocation

When the AI determines a Skill is relevant, it's automatically added to the context:

vibe/core/agent/loop.py
# Before model inference
def _prepare_context(self, user_message: str) -> str:
    context = self._build_base_context()
    
    # Check for model-invocable skills
    for skill in self._skill_manager.available_skills.values():
        if skill.model_invocable:
            # Model decides if Skill is relevant based on description
            if self._model_should_invoke(user_message, skill):
                context += f"\n\n--- Skill: {skill.name} ---\n"
                context += skill.prompt
    
    return context
Relevance Check
def _model_should_invoke(self, message: str, skill: SkillInfo) -> bool:
    """Check if skill description matches user message"""
    # Simple implementation: check if description keywords appear in message
    description_keywords = skill.description.lower().split()
    message_lower = message.lower()
    
    # More sophisticated: use embedding similarity or LLM judgment
    return any(keyword in message_lower for keyword in description_keywords)

Registry Integration

Vibe can fetch Skills from a central registry, so you don't have to create everything from scratch.

How the Registry Works

The registry is a central catalog of Skills published by Mistral AI and the community. Think of it like a package repository (similar to npm, pip, or apt).

Browsing Available Skills

You can discover Skills published to the registry and add them to your local setup. Each Skill in the registry has:

  • ✓ A unique identifier (like mistralai/code-review-pro)
  • ✓ Multiple versions
  • ✓ A description explaining its purpose
  • ✓ The complete Skill content (instructions, configuration, etc.)

Adding Skills from the Registry

When you want to use a Skill from the registry, you pin it to your skills.toml file. This tells Vibe: "I want to use this specific Skill". Vibe then downloads and caches it locally.

~/.vibe/skills.toml
[[skills]]
name = "code-review"
skill_id = "mistralai/code-review-pro"
version = "latest"
description = "Professional code review assistant"

[[skills]]
name = "django-expert"  
skill_id = "mistralai/django-guide"
version = 2
description = "Django framework specialist"
ℹ

Global vs Project Skills: You can pin Skills globally (in ~/.vibe/skills.toml - available everywhere) or per-project (in .vibe/skills.toml - only in this project). Project pins override global ones with the same name.

Version Management

Registry Skills use versioning, just like software packages. This ensures you get predictable behavior.

Pin to a Specific Version

version = 2

Always uses exactly version 2, ensuring consistency

Use "latest"

version = "latest"

Always fetches the newest version (may change over time)

Custom Aliases

alias = "stable"

Use your own named versions for easier management

What Happens When You Update?

When Vibe starts or when you run a sync command, it checks your pinned Skills:

  1. Read your manifest - Checks what Skills you've pinned
  2. Check local cache - Sees if you already have the requested version
  3. Download if missing - Fetches any Skills not in your cache
  4. Validate and store - Saves Skills safely with atomic writes (preventing corruption)
  5. Make them available - Skills are now ready to use just like local ones
