What is a Skill?

A Skill is a set of custom instructions that you can add to Mistral Vibe to teach it how to better assist you with specific tasks or workflows.

Think of Skills as "plugins" or "extensions" for Vibe's brain. Each Skill contains:

  • ✓ Metadata - Name, description, and configuration
  • ✓ Instructions - The actual guidance for the AI
  • ✓ Scope - Global (all projects) or Project-specific
  • ✓ Access Control - Who can invoke it (you or the AI)
my-skill/SKILL.md
---
name: code-review
description: Load when reviewing pull requests
user-invocable: true
---

# Code Review Guidelines
1. Check for security vulnerabilities
2. Verify all tests pass
3. Ensure code follows PEP 8
ℹ

Skills are Markdown files with YAML frontmatter. The YAML defines the metadata, and the Markdown body contains the instructions.

🔗

How to Use Skills

Invoke a Skill Manually

Type /skill-name to explicitly use a Skill:

/code-review

Review this pull request for me

List Available Skills

To see all available Skills:

/skills
Vibe CLI
> /code-review
Loaded skill: code-review

Automatic Skill Loading

Vibe can automatically load Skills based on context. The AI reads the description field and decides if it's relevant.

If a Skill has description: Load when working with Django, and you ask about Django, Vibe will auto-load it.

ℹ

Model-only Skills: Set user-invocable: false to hide from / menu but allow AI auto-loading.

→

Proceed normally

1

Choose Location

  • Global: ~/.vibe/skills/
    All projects
  • Project: .vibe/skills/
    This project only
2

mkdir -p ~/.vibe/skills/my-skill
touch ~/.vibe/skills/my-skill/SKILL.md
3

Add YAML Frontmatter

---
name: my-skill
description: Load when helping with data analysis
user-invocable: true
license: MIT
---

# Instructions go here

Fields:

Required: name, description

Optional: user-invocable, disable-model-invocation, allowed-tools, license, metadata

4

Write Instructions

# Python Best Practices

## Code Style
- Follow PEP 8 guidelines
- Use type hints
- Limit lines to 88 chars
5

Reload & Use

/reload
/my-skill Help me!

Core Components

The Skills subsystem in vibe/core/skills/ consists of these key modules:

📄 models.py

Data models for Skills

  • SkillMetadata - Frontmatter fields
  • SkillInfo - Complete skill data
  • SkillSource - BUILTIN/LOCAL/REGISTRY/PLUGIN
  • SkillScope - GLOBAL/PROJECT/BUILTIN

📝 manager.py

Core Skill management

  • SkillManager class
  • Discovery logic
  • Filtering (enabled/disabled)
  • LRUCache for parsed skills

📂 parser.py

File parsing

  • YAML frontmatter extraction
  • Markdown body separation
  • OpenAI compatibility
  • Validation

🛡 builtins/

Built-in Skills

  • vibe - CLI awareness
  • skill-creator - Guide

🌎 registry/

Registry integration

  • Client API
  • Manifest management
  • Store/caching
  • Sync operations

Skill Invocation

User-Triggered Skills

When user types /skill-name:

  1. SkillManager.parse_skill_command() called
  2. Lookup skill by name in available_skills
  3. Check user_invocable is true
  4. Return ParsedSkillCommand with skill content
  5. Skill prompt added to model context
manager.py
def parse_skill_command(self, text_prompt: str):
    if not text_prompt.strip().startswith("/"):
        return None
    skill_name = text_prompt.strip()[1:].split(None, 1)[0].lower()
    skill_info = self.get_skill(skill_name)
    if skill_info is None or not skill_info.user_invocable:
        return None
    return ParsedSkillCommand(
        name=skill_name,
        content=skill_info.prompt,
        extra_instructions=...
    )
User Invocation
> /my-skill Do this
[Skill loaded: my-skill]

AI-Triggered Skills

When model determines a Skill is relevant:

  1. Agent processes user message
  2. Model compares to description fields
  3. Check model_invocable is true
  4. Skill prompt added to system message
  5. Model generates response with context

Registry Skills

Registry Integration

Skills can be synced from a central registry:

Key Files:

  • ✓ _client.py - HTTP API client
  • ✓ _manifest.py - TOML manifest handling
  • ✓ _store.py - Local cache at $VIBE_HOME/registry/skills/store/
  • ✓ _ledger.py - Cross-repo version tracking

Manifest Example:

~/.vibe/skills.toml
[[skills]]
name = "code-review"
skill_id = "mistralai/code-review"
version = "latest"
description = "Code review assistant"

[[skills]]
name = "django-expert"  
skill_id = "mistralai/django"
version = 2
Cache Structure:
$VIBE_HOME/registry/skills/
├── store/
│   └── {skill_id}/
│       └── {version}/
│           ├── SKILL.md
│           └── assets/
├── ledger/
│   └── {repo_hash}.txt
└── seen-versions.json

Configuration

Vibe Configuration

~/.vibe/config.toml
# Additional skill search paths
skill_paths = ["/path/to/skills"]

# Enable/disable skills
enabled_skills = ["vibe", "custom-*"]
disabled_skills = ["experimental-*"]

# Registry (experimental)
experimental_enable_registry_skills = true

Pattern Matching:

  • ✓ Exact: "vibe"
  • ✓ Glob: "custom-*"
  • ✓ Regex: "re:^test-.*"
ℹ

Discovery Order:

  1. Built-in skills (reserved names)
  2. Config skill_paths
  3. Project skills (.vibe/skills/)
  4. User skills (~/.vibe/skills/)
  5. Registry skills

First match wins!
